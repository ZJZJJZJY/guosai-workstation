# 协作分工 — 方向统一，不做无谓辩证

## 总原则
1. **唯一方向**：全队围绕"国奖标准"朝**同一套方案**收敛，不搞正反方辩论。
2. **分工 = 互补，不是对抗**：三位各管一摊，互为增强。
3. **意见合并规则**：专家意见不同时，由 Claude 一次性合并成**唯一**最优方案（取共识/最优折中），不再多轮往返；仅在"是否达国奖线"上留一个最终把关。

## 分工矩阵
| 角色 | 谁 | 强项 | 负责 | 输出 |
|---|---|---|---|---|
| 总指挥 + 执行 | Claude Code（VSCode 插件） | 本地动手、编排、跑代码、读 state、调用技能、与用户交互 | 建流水线、写并渲染出图、整合 DeepSeek 结果、排版、**统一合并各方意见并拍板** | 唯一方案 + 落地文件 |
| 数据与数值顾问 | DeepSeek Harness（VSCode 插件） | 批处理、数据分析、数值实验、工具调用 | 数据清洗、基线实验、求解/仿真、联合灵敏度、全量复算 | 可复现代码 + 结果表 + 指标报告 |
| 内容与呈现顾问 | GPT / Codex（VSCode 插件） | 语言、批判、文本打磨、风格判断 | 模型选型建议、摘要/论文审校、图表与配色建议、行文学术化、最终正确性抽检 | 单条推荐 + ≤3 增强点 + ≤1 风险 |
| 严谨复核（红队） | GPT / Codex，`rigor` persona | 异构于编排者，复核才有独立性 | 关键小问数值对标官方答案、假设合理性、灵敏度是否多变量联合、模型与实现一致、附录代码完整性 | 同上 |

> 为什么严谨顾问也是 GPT：Claude Code 本身就是 Opus 5，再调一次同型号做"独立复核"
> 拿不到独立视角（同模型自评），只增加成本与故障面。故合并给异构的 GPT。

## 统一入口

```bash
cd <skills>/national-award-captain/multi_ai
python advise.py --stage <0-9> --text "..."        # 按阶段自动派活、并行、降级
python advise.py --stage 9 --file paper/draft.md --json state/advice_s9.json
python advise.py --stage 5 --only deepseek --text "..."
```

阶段路由表见 `advise.py: STAGE_ROUTING`；完整说明见 `docs/opus5-integration-requirements.md`。

## 流程
1. Claude 给出一版方案/产出。
2. DeepSeek 先完成数据与数值产出；GPT 对方案和论文给「推荐 + 增强点 + 风险」，**方向一致不抬杠**。
3. Claude 把两方增强点合并成**唯一**最优方案；若冲突，当场取共识并把理由写进 decision_log。
4. （终审，可选）终审把关做一次总测，只给结论 + 最优先补强的 2 件事，不展开辩论。

## 红线
- 不允许输出"两套对立方案"给用户选择题；只给**一套已拍板**的方案。
- 不进入多轮来回辩；意见分歧一次裁决，记录于 `cwd/state/decision_log.json` 的 events。
